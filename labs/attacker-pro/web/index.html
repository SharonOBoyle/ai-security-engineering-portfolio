How to read the live console

RedCell attacks a target AI over a series of episodes (one attempt each), then prints a summary.

Each episode — one attack attempt

objective
the banned behaviour being tested — a short code plus a plain description, e.g. PCI — full card number read-back.
strategy / family
the exact attack recipe used (ID + title), and the group of recipes it belongs to.
via / conv
how the messages are sequenced (single, slow build-up, branching…) / how they're disguised (none = sent as-is).

Planner ranking — which family to try next

planner rank / ▶
families ordered by what's most worth trying next — a priority order, not a success rate; ▶ marks the one chosen this episode.
history W/P
past results this campaign: W wins of P attempts. The order also favours less-tried families, so the best rate isn't always rank 1.

The conversation

→ you / ← tgt
the attacker's message / the target AI's reply.
[warm-up] [escalate] branch
the stage or variant of a multi-step attack a message belongs to.

Did it work?

✓ HIT / ✗ HELD
the attack reached its objective with hard evidence (still a candidate until verification reproduces it) / it didn't this episode.
canary / flag
the proof behind a HIT: a planted secret that should never appear / the target reporting a forbidden action.
opportunistic find
a different objective that leaked in the same reply, caught while testing another.

End-of-run summary

saved family history
per-family totals across all runs here — attempts tried and primary hits (main objective reached); control is excluded, so its hits stay 0 (0 is good).
candidates banked
findings saved this run, split into primary / opportunistic / control and listed by ID.

Other labels

brains …=code
optional LLM help is off; the deterministic fallback code is running.
started / finished · duration
when the run began and ended, and how long it took.
